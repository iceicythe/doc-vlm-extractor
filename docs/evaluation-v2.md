# 评分协议 v2.0.0

实现：`src/scoring.py`。本地评测、API 评测、历史重算、偏好质量检查共用该模块。
本协议改变历史口径；旧分数不能与 v2 混排。数据 Schema 仍为 materials-v1。

## 字段比较

| 字段 | 规则 |
|---|---|
| 名称、规格、单位、项目、供应商、编号、序号、电话 | NFKC 全半角兼容归一化、去首尾空白；保留内部空白、标点、单位、前导零 |
| 明细数量/单价/金额、合计金额 | 字符串以 Decimal 精确比较；不使用 float 或有效位截断 |
| 日期 | 仅支持完整 YYYY-MM-DD、YYYY/MM/DD、YYYY.MM.DD、YYYY年M月D日，校验真实日历日期；不猜月日顺序 |
| 缺失、null、空字符串 | 字段 F1 中均视为没有提取值，与 0 区分；必填字段的三种情况均不能通过 Schema |
| 非字符串叶子 | 类型错误，不能仅因转字符串后与 GT 一致就算正确 |

数值仅接受普通十进制（可带正负号）；千分位必须三位分组，如 `1,234.50`。
不接受货币符号、单位后缀、科学记数法、NaN、Infinity；不擅自删除这些字符。
Decimal 格式化也不调用可能受默认精度影响的 normalize()。
日期缺失与空值按上表处理；非空但格式不支持时判错误。

`normalize(value)` 不带路径时只清理文本。调用者必须传字段路径才能启用数值/日期比较。
明细“金额”和合计“金额”纳入金额准确率；数量和单价纳入字段 F1，但不纳入金额准确率。

## 明细与结构

主指标固定为**阅读顺序按数组下标对齐**。序号也是普通标识符字段。
序号缺失或重复时仍按下标比较，不自动寻找更相似的行；重排会产生错误。
多行计 FP，漏行计 FN，重复行按额外行处理；格式损坏的行保留位置，不把后面的行前移。
整单正确包含顺序要求。本版本没有内容匹配辅助指标。

Schema 检查：顶层四项必填，单据类型为“材料清单”；表头四项必填；合计金额必填；
明细 1–8 行，各行除规格型号外全部必填。所有叶子为字符串，必填值非空。
各层不允许额外字段；数值和日期字符串还需满足上述格式。
规格型号缺失、null、空串在字段 F1 中不产生目标值，但 null 仍违反字符串类型。
GT 应先通过校验；真实图像的不可读/遮挡状态尚未引入这个 Schema。

错误结构在所在路径贡献一个 FP，同时其下应提取字段计 FN；额外子树在其根路径贡献一个 FP，
包括空对象或 null。普通错误值贡献一个 FP 和一个 FN。单据类型也计入字段 F1。
路径标点会转义，防止额外字段名称冒充合法嵌套路径。

## 指标与分母

| 指标 | 分母/定义 |
|---|---|
| strict_json_valid_rate | 原始整段文本直接解析为合法 JSON / 全部样本；拒绝重复键、NaN、Infinity；合法数组/标量可通过 JSON 语法检查 |
| loose_parse_success_rate | 容许代码围栏、前后解释后得到对象 / 全部样本；合法数组/标量不作为对象救回 |
| schema_valid_rate | 宽松解析出的对象符合 Schema / 全部样本 |
| precision / recall / f1 | 全部样本累计 TP/FP/FN 的 micro 指标；解析失败时 GT 字段全计 FN |
| amount_accuracy | 金额字段正确数 / GT 中应提取金额字段数，缺失与解析失败均算错误 |
| document_correct_rate | 严格 JSON、Schema 合规、全部目标字段及明细顺序正确 / 全部样本 |
| extra_field_sample_rate | 存在 Schema 外字段的样本 / 全部样本；不是幻觉率 |

每项同时保存正确数、分母或 TP/FP/FN。无金额目标时金额准确率为 null。
`score_pred` 只检查已解析对象，无法知道原始 JSON 合法性；正式原始输出报告用 `score_one`。
`tolerant=True` 仅提供“合计标量转对象”的辅助字段 F1，Schema 仍检查原对象，不用于整单通过。
保留 `json_valid` 作为宽松解析的兼容别名；`hallucinated_keys` 作为历史接口别名仅表示多出目标路径，
不能作为无依据生成的证据。新版汇总不再输出 hallucination_rate。

推理失败和解析失败不同。历史预测没有明确推理状态时 inference_failure_count 为 null，
不能因为文本非空就推断推理成功。在线入口异常中止时不输出不完整汇总；保存的预测可用于恢复。
评分程序自身异常直接报错，不跳过样本生成虚高分数。

## 跨域 flat 模式

与材料清单单独报告。允许字段：store_name、store_addr、tel、date、time、subtotal、tax、total。
这些键区分大小写，不做键名模糊匹配；字段可选，叶子必须为字符串。
subtotal、tax、total 为金额；tel 为标识符。其他字段仅做文本清理。
当前真实收据日期格式可能超出本协议支持范围；扩大格式范围前应版本化并重新评测，不能临时猜测。

## 真实图像标注边界

现有 v1 GT 为合成完整字段。本轮没有新真实单据，也没有把模型输出用作 GT。
后续真实试点应在独立标注元数据中逐路径记录 `readable`、`not_present`、`unreadable`、`occluded`、
`blank`，并经人工核对；不可读或遮挡不能一律标 0 或空字符串。
尚未实现按这些状态屏蔽字段的评分；在数据规范和掩码策略定稿前，不将此类样本并入 v2 汇总。
