# 广联达图文多模态实习 · 8GB 显存项目方案

> 目标岗位：图文多模态模型下游算法研究（自动化 prompt 生成 / 知识注入 / 强化学习）+ 图片结构化提取、图片内容理解落地 + 多模态 agent
> 硬件约束：RTX 4060 Laptop 8GB
> 核心策略：**本地小模型做"落地载体"，云端 API 大模型做"老师/评测器/agent 大脑"**——这本身就是企业落地的真实范式，面试叙事非常顺。

---

## 一、8GB 显存能干什么（可行性清单）

| 任务 | 方案 | 8GB 可行性 |
|---|---|---|
| VLM 监督微调 (SFT) | Qwen3-VL-2B / 4B + QLoRA 4bit (Unsloth) | ✅ 2B 宽裕，4B 约 6GB |
| VLM 偏好优化后训练 (DPO) | Qwen3-VL-2B/4B + Unsloth/LLaMA-Factory + QLoRA | ✅ 显存占用与 SFT 相当，4B 也能跑 |
| 4bit 推理 | 7B~8B 级 VLM（Qwen3-VL-8B 等） | ✅ 4bit 量化推理流畅 |
| 视觉检索 / 知识注入 | ColPali 类模型 LoRA、多模态 RAG | ⚠️ 需小图 + 小 batch |
| Agent | 大脑走 API（DeepSeek/GLM/通义），本地只跑工具 | ✅ 几乎不占显存 |
| 全参微调 7B+ / 长视频训练 | — | ❌ 不要碰 |

实操要点：
- **Windows 原生环境起步**（Unsloth 官方支持）：装 triton-windows、训练脚本开头加 `os.environ["TORCHDYNAMO_DISABLE"] = "1"`、SFTTrainer 里 `dataset_num_proc=1`；只有反复被环境问题卡住时再考虑 WSL2；
- batch=1 + gradient_accumulation 4~8、NF4 双重量化、gradient checkpointing、图片统一 resize 到 384~512px；
- 笔记本插电 + 散热支架，训练时关掉浏览器（显存被占 1GB 就 OOM）；
- 在线 RL（GRPO）不纳入本项目范围：8GB 笔记本上风险高、收益低，DPO 已足以承载"后训练"叙事。

## 二、主项目（必做）：小模型文档图片结构化提取流水线

**一句话**：把"单据/表单/表格图片"端到端转成结构化 JSON，用 QLoRA 微调一个 4B 以下 VLM，达到接近 API 大模型的效果，成本低一个数量级。

直接对应 JD 第 2 条"图片结构化提取、图片内容理解"，且广联达是建筑信息化公司，图纸、造价单据、工程报表正是他们的真实场景。

### 技术路线
1. **基座**：Qwen3-VL-4B-Instruct（QLoRA，8GB 够）；
2. **数据**（重点，占 50% 工作量）：
   - **主力公开集**：WildReceipt（1765 张收据，25 类 key-value 标注，PaddleOCR 官方直链 `wget https://paddleocr.bj.bcebos.com/dygraph_v2.1/kie/wildreceipt.tar`，且有 SDMGR 官方基线数字可引用）+ CORD（1000 张小票，字段级 JSON，HuggingFace 可下）；
   - **中文公开集的现实**：EPHOIE（中文 key-value）需申请+提交论文证明，学生拿不到——中文场景直接用自建合成数据覆盖；
   - **合成数据是亮点**：自己写 HTML/渲染管线生成"工程单据风格"表格图（随机表头、金额、印章、倾斜、噪声，1000~2000 张中文样本），标注天然免费——模拟企业"没有现成标注数据"的真实困境；
   - 用便宜 API（DeepSeek/GLM-4.5-flash 级别）蒸馏标注 + 人工抽检 100 张算一致性；
   - **测试集划分**：CORD test + WildReceipt test + 合成数据留出集做主评测；FUNSD（199 张表单，不参与训练）做零样本泛化测试；
   - 不用 DocVQA（QA 型而非提取型）、不碰 PubTabNet（50 万张，8GB 训不完）；
3. **微调**：Unsloth QLoRA SFT，输出约束为 JSON schema；
4. **评测**：字段级 F1 / ANLS，做一张对比表：
   - PaddleOCR+规则基线 vs 未微调 VLM vs 微调后 VLM vs GPT-4o 级 API；
   - 同时报告**准确率和单张推理成本**（这个对比表就是简历上最硬的一行）；
5. **展示**：Gradio demo（拖图→出 JSON）+ GitHub README + 一篇技术博客（数据构造踩坑 + 显存优化）。

### 加分模块 A（二选一或都做精简版）：DPO 偏好优化后训练

**为什么是 DPO 而不是 GRPO**：在线 RL 每步要采样多个回答，KV cache 显存峰值高、没有 vLLM 采样慢、调参坑多，8GB 笔记本上风险太大；DPO 是离线训练，显存占用和 SFT 相当，本地稳跑。

**完整流程（这套叙事比单纯 GRPO 更完整）**：
1. **设计可验证 reward 函数**：`JSON 合法性 + 字段级 F1 − 幻觉惩罚`（输出标注里不存在的字段扣分）；
2. **构造偏好数据**：用 SFT 后的模型对每张验证图采样 4~8 个输出（temperature 0.7~1.0），reward 打分，最高分作 chosen、最低分作 rejected；
3. **DPO 训练**：Unsloth（TRL DPOTrainer）或 LLaMA-Factory（`stage: dpo`），QLoRA 配置同 SFT；
4. **评测**：base → SFT → DPO 三档对比，看字段 F1 / JSON 合法率 / 幻觉率的提升曲线。

- 对应 JD 第 1 条"强化学习"——DPO 本来就是后训练/对齐的主流手段之一，叙事同样成立；
- 常见坑：偏好对差距太小（分差 < 阈值的对丢弃）、DPO 后 JSON 合法率可能不升反降（reward 权重需调）——踩过并解决这些坑，面试可讲的东西反而更多。

### 加分模块 B：自动化 prompt 优化
用 DSPy / APE / PromptWizard 思路，把"人工写提取 prompt"变成"优化器模型自动搜索 prompt"：
- 执行器 = 本地微调后的小模型或 API 模型；优化器 = API 模型；
- 画出"自动优化轮数 vs 验证集准确率"曲线，对比手写 prompt——对应 JD 第 1 条"自动化 prompt 生成"，纯 API 成本 < 10 元。

## 三、展示项目（强烈建议）：把主项目包成"图片理解 Agent"

对应 JD 第 3 条。在主项目之上加一层 agent 循环：

```
用户输入图片/问题
   ↓ Agent（API 模型做大脑，函数调用）
   ├─ 工具1：PaddleOCR 精确文字定位
   ├─ 工具2：目标检测/版面分析（裁剪 ROI 再放大识别）
   ├─ 工具3：本地微调 VLM（结构化提取）
   ├─ 工具4：多模态检索（ColPali/CLIP 查图纸知识库）
   ↓ 汇总 → 输出答案 + 带溯源的 JSON
```

- 亮点：**小模型 + 工具组合逼近大模型效果**，含失败重试、幻觉自检（跨工具交叉验证）；
- 演示场景可以往建筑/造价靠：如"上传一张工程签证单照片 → 自动提取条目金额汇总"；
- Gradio 一页 demo 即可，agent 部分几乎不占显存。

## 五、简历写法示例

> **文档图片结构化提取系统（个人项目）**：针对建筑单据场景，构建"合成数据渲染 + API 蒸馏标注"数据管线（X 条样本）；基于 Qwen3-VL-4B 进行 QLoRA 微调（8GB 消费级显卡），字段级 F1 从 0.XX 提升至 0.XX，达 GPT-4o 级效果的 XX%，单张成本降低 XX 倍；设计可验证 reward（JSON 合法性 + 字段 F1 − 幻觉惩罚），采样构造偏好数据做 DPO 后训练，JSON 合法率提升至 XX%、幻觉率下降 XX%；封装为多模态 agent（OCR 定位 + ROI 裁剪 + VLM 提取 + 检索溯源），含 Gradio 演示与完整评测报告。

面试必问预备：数据怎么造的/怎么防蒸馏标注的噪声、为什么 QLoRA 有效、reward 函数怎么设计、chosen/rejected 怎么构造、DPO 与 PPO/GRPO 的区别、和 OCR 传统方案的边界、8GB 怎么塞下训练——每个都能从项目里拿出真实数字回答。
