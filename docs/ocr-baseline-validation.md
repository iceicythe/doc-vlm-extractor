# OCR 基线验证记录

- OCR 在独立 `.venv-ocr` 中安装并运行；原微调环境未安装或升级依赖。
- 固定 `RapidOCR ONNX Runtime 1.4.4`、`ONNX Runtime 1.20.1` 等版本，完整依赖见 `requirements-ocr-lock.txt`。
- 规则仅接收图片和 OCR 文字框，不接收 GT、样本 ID、材料词表或供应商名单。GT 只由外层评分器使用。
- 验证集前 8 个源单据共 24 张用于开发；规则修订一次。源码、模型与配置在正式测试前冻结。
- 规则测试 7 项通过：字段提取、列顺序变化、缺失字段不猜测、未知类型、名称换行、输入不变、漏标题不并列。
- 正式测试 102 张全部完成，推理/规则异常为 0。原始 OCR、坐标、置信度、列边界及字段来源均已保存。
- 测试集来自 83 个源单据，三档各 34 张；不能把 102 张视为 102 个独立来源。
- 核验开发与测试源单据无交叉；逐张核验 102 个图片内容哈希、GT、样本顺序和汇总重算一致。
- 四方案使用相同图片 ID 顺序和 GT。历史词表 `pred_orig` 逐条等于对应微调生成文本。
- 测试后复查规则、评分器、OCR 模型及配置哈希与冻结记录完全相同，没有依据测试结果改规则。
- P0 清单记录的历史预测、汇总、缓存和数据文件哈希未变。
- 新增 Python 文件编译通过，`git diff --check` 通过。

时延只测量本轮 OCR CPU 推理；未将旧历史汇总里的“仅评分耗时”冒充 VLM 推理时间。
OCR 测试后完成失败案例回查，未据此修订规则。若以后优化，应另设最终留出测试集。

参见 [四方案报告](ocr-baseline-report.md)。陌生版式是独立的后续配对试点，不能与上述 102 张混为一个总体成绩。
