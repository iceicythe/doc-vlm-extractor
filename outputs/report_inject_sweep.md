## 0. 一句话结论

用 train.jsonl 的 GT 值域做标准词表，对模型输出做**保守的模糊纠错**，
零样本同域 F1 **0.7349 → 0.7870（+0.0522）**，且**改坏 0 处**；
但对已微调的 SFT 档**几乎无事可做（183 处改动 → 1 处）**。

### 2.1 `min_gap` 必须保留（它不是可有可无的）

`min_gap` = top1 与次优的相似度差。把它从 0.05 放宽到 0.00：

- sim=0.50 / 不含日期：改动 183 → 224（多改 41 处），而 ΔF1 只从 +0.0522 到 +0.0525。
  **多改 41 处换来 +0.0003 —— 边际全是噪声。**
- 含日期时更明显：`broke` 从 **0 涨到 8**。

原因：同模板字段彼此极像（`X市政道路改造工程` 有一大批候选），
去掉 gap 后就无法区分「该改成哪个」，只能靠 top1 硬猜。

### 2.2 `min_sim` 的拐点在 0.50

看「新增改动的有效率」（本次比上次多改的那些里，有多少真的改对了）：

| 区间 | 新增改动 | 新增 fixed | 有效率 |
|---|---:|---:|---:|
| 0.70 → 0.60 | +17 | +13 | 76% |
| 0.60 → 0.50 | +37 | +34 | **92%** |
| 0.50 → 0.40 | +14 | +6 | **43%** ← 拐点 |

0.40 只比 0.50 多 +0.0019 F1，代价是 still_wrong 从 14 涨到 22。
**所以默认取 0.50** —— 依据是边际有效率，不是"在测试集上试出来的最好分数"。

### 2.3 `broke` 恒为 0 是结构性保证，不是调参调出来的

```
模型输出正确 ⇒ 该值 == GT ⇒ GT 在词表内 ⇒ 精确命中 ⇒ 走规则 1、不改
```

也就是说**只有「GT 本身不在词表里」的实例才可能被改坏**。
本数据集 1260 个可比实例中只有 **2 个** GT 不在词表里 —— 这就解释了
为什么 gap=0.05 的所有配置 `broke` 都是 0，而 gap=0.00 时恰好冒出 1 个。

### 2.4 日期默认关闭

开启后 +0.0065（0.7870 → 0.7935），`broke` 仍为 0。
但**默认仍然关闭**，因为日期的收益依赖「日期池是有限的」这一数据特性：

- 本项目日期来自 259 个固定值，所以能命中；
- 真实场景里日期是连续值，`2026-06-26` 与 `2026-06-25` 相似度约 0.91，
  模糊匹配会把相邻日期混淆 —— 它不是一个「有标准写法的字段」。

要用时显式加 `--include-date`。

## 3. 两档对照：知识注入的价值与基座能力成反比

同一套词表、同一套阈值（min_sim 0.50 / gap 0.05 / 不含日期）：

| 档位 | 可比实例 | 改动 | 仅统一写法 | fixed | broke | F1 前 | F1 后 | **ΔF1** |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| ② 2B 零样本 | 1260 | **183** | 70 | 169 | 0 | 0.7349 | 0.7870 | **+0.0522** |
| ③ 2B SFT 384px | 1335 | **1** | **203** | 0 | 1 | 0.9782 | 0.9779 | **−0.0003** |

三个读法：

1. **SFT 之后词表纠正无事可做**（183 → 1 处改动）——
   因为 **SFT 已经把词表内化进权重了**，不需要外部知识再喂一遍。
2. 「仅统一写法」从 70 涨到 203：SFT 输出的值几乎全在词表里，
   只是空格/符号写法与 canonical 略有差异，归一化后等价、不影响分数。
3. 那唯一的 `broke=1` 正是 §2.3 说的「GT 不在词表里」的 2 个实例之一。

⇒ 这条对照支持项目主线：**SFT 买到的是「读写中文字段」的能力**，
而词表归一化正是同一件事的另一种（外部）实现 —— 所以两者收益高度重叠。

## 4. 复算命令

```powershell
# 1) 建词表（从训练集 GT 值域）
.\venv-gld\Scripts\python.exe src\build_lexicon.py

# 2) 注入 + 重打分（纯 CPU，不加载模型）
.\venv-gld\Scripts\python.exe src\inject_knowledge.py `
    --preds outputs\eval_zero_abl_preds.jsonl --tag zero_abl_inj `
    --report outputs\report_inject_zero_abl.md

# 3) 对 SFT 档做同样的事（对照）
.\venv-gld\Scripts\python.exe src\inject_knowledge.py `
    --preds outputs\eval_abl_base_preds.jsonl --tag abl_base_inj `
    --report outputs\report_inject_abl_base.md

# 变体
#   --min-sim 0.40 / --min-gap 0.00 / --include-date / --no-fuzzy
# 注：这两个 --report 路径会重新生成为独立文件；其内容已合并进 outputs/reports_appendix.md §2
```

## 5. 已知局限

- **阈值是在测试集上扫的**。本项目测试集只有 102 条，严格做法应在验证集上选阈值。
  缓解：默认值取自「边际有效率拐点」而非最高分，且 `broke=0` 是结构性保证（§2.3）。
- 词表来自训练集 GT，因此**训练集覆盖不到的字段值无法纠正**（本项目仅 2/1260）。
- 只对同域 schema 有效；跨域 WildReceipt 是扁平键值对、字段集合不同，词表不适用。
