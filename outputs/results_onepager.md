# MiniVLM · 一页 Results

> **面向工程材料清单的图文多模态结构化抽取**
> Qwen3-VL-2B + QLoRA · 单卡 RTX 4060 Laptop 8GB · 2026.07–2026.09

---

## 0. 一句话

把一张**工程材料清单/结算单**照片，直接抽成结构化 JSON
（表头：项目名称/供应商/单据编号/日期 · 明细：序号/名称/规格型号/单位/数量/单价/金额 · 合计），
在**消费级 8GB 显卡**上完成从数据构造到微调、对比、Demo 的全链路，字段级 F1 **0.982**。

场景与 **BIM / 造价 / 施工单据**同构 —— schema 就是造价软件的「材料明细表」。

## 1. 主表：五档对比（同一测试集，同一打分口径）

| 档 | 实现 | 同域 F1<br>（消融子集 n=102） | 跨域 F1<br>（英文收据 n=100） | 状态 |
|---|---|---:|---:|---|
| ① 规则基线 | OCR + 正则 | — | — | 未做 |
| ② **2B 零样本** | `--adapter` 留空 | **0.7349** | 0.319 | ✅ |
| ②+ 知识注入 | 词表约束纠错（不需训练） | **0.7870**（+0.0522） | — | ✅ |
| ③ **2B 微调后** | QLoRA 384px | **0.9782** | 0.284 | ✅ |
| ③+ 知识注入 | 同上 + 纠错 | 0.9779（±0） | — | ✅ |
| ④ 8B 零样本 | Qwen3-VL-8B 4bit | — | — | 未做 |
| ⑤ 商用 API | `deepseek-flash`（`--no-thinking`，¥1.9 / 202 张） | 0.9681 | **0.4408** | ✅ |
| ⑤+ 知识注入 | 同上 + 词表纠错 | **0.9790**（+0.0109） | — | ✅ |

**主结果（同分布测试集 n=90）**：字段级 F1 **0.982**（clean 0.994 / medium 0.982 / heavy 0.961），
JSON 合法率 **100%**，幻觉率 **0%**，训练 600 步 / 58.7 分钟 / 峰值显存 **4.03 GB**。

**两个最该记住的差值：**
- **② → ③ 同域 +0.2433** —— 这是「微调买到了什么」的直接证据。
- **同域 2B 微调 0.9782 ≈ 商用 API 0.9681（差 1.0pt），而跨域反过来（0.284 vs 0.4408）。**
  闭集固定版式的领域任务上，2B 微调就能追平大模型；跨语言跨域才是大模型的主场。

> ⚠️ **跨域列的读法（别被它误导，这是主动交代的口径限制）：**
> 该列用的是内置 `PROMPTS["flat"]`，只要求抽 **3 个字段**。WildReceipt 真值 100 条共 **643 个字段**
> （平均 6.43），其中只有 **268** 个被点名 ⇒ **recall 天花板 = 268/643 = 0.4168**。
> ⑤ 档的 0.4408（recall 0.3157）是该天花板的 **75.7%** —— 还有 24pt 空间，不是"贴着"。
> 把字段清单补到 8 个（天花板 → **0.9907**）后，⑤ 档跨域 **0.4408 → 0.7085**（见 §2 结论 ⑤/⑥）。
> 所以这一列**衡量的是「prompt+模型」的组合，不等于模型在该域的感知能力**。
>
> **本地 ②/③ 换 8 字段的对照已跑完**：召回同样翻倍（0.230→0.496、0.208→0.418），
> 但精确率同时塌掉、幻觉率飙到 **0.59 / 0.73**（照着 8 个字段名逐条填空，抽不出来就编）。
> 换成「天花板达成率」看：② 55%→50%、③ 50%→42%、⑤ 76%→73% —— **同档换 prompt 几乎不动，
> 50% vs 73% 这个跨档差距才是真的**。**该列保持 3 字段口径可比，不要单独把 0.7085 填进来。**

## 2. 五条能讲出口的结论

**① 输入分辨率是主导因素，不是数据量。**
6 组消融（384/512/768px × 数据 25/50/100% × 冻结视觉塔）显示：384→768px 总体 F1 0.9782→**0.9953**，
增益**全部来自重度退化档**（0.9635→0.9870）；数据量 25%→100% 只涨 1.2 个点且增量递减。
⇒ 训练集 700 个源样本（×3 档退化 = 2100 张）已接近饱和，堆数据的边际收益低于换更大输入。

**② 「冻结视觉塔几乎没有代价」把 2B 塞进了 8GB。**
仅训语言层 0.9790 vs 全层 0.9782，差 0.0008（不到 3 个字段，属噪声）。
⇒ 显存紧张时可以放心不训视觉塔。

**③ 知识注入的收益与基座能力成反比 —— 这条最能在面试里展开。**
用训练集 GT 值域建标准词表，三级保守规则（精确命中→相似度 ≥0.50 且 gap ≥0.05→原样保留）：

| 档位 | 改动 | 修复 | **改坏** | ΔF1 |
|---|---:|---:|---:|---:|
| ② 2B 零样本 | 183 | 169 | **0** | **+0.0522** |
| ⑤ `deepseek-flash` | 40 | 37 | **0** | **+0.0109** |
| ③ 2B SFT | **1** | 0 | 1 | −0.0003 |

三个档位连成一条**单调曲线**：基座越弱，词表约束的收益越大；SFT 之后只剩 1 处可改 ——
**词表已经被微调内化进权重了**。而且 ⑤+注入（0.9790）与 ③（0.9782）已经**追平**
（差 0.0008，在噪声内 —— 只说追平，不说反超）：
**这一层纯 CPU 的约束，等价于把商用模型顶到专门微调的水平。**

`broke ≡ 0` 是**结构性保证**：输出正确 ⇒ 值等于 GT ⇒ GT 在词表内 ⇒ 精确命中 ⇒ 不改。

动手前先做了可行性前置检查，推翻了「错误率高的字段最该救」的直觉：

| 字段 | 词表值数 | 测试集命中率 | 零样本错误率 | 结论 |
|---|---:|---:|---:|---|
| 供应商 | 692（随机） | 1.0% | 87.8% | ✗ 正确值不在词表里，救不了 |
| 单据编号 | 698（随机） | 0.0% | 79.6% | ✗ 同上 |
| 名称 / 规格型号 | 20 / 37 | 100% | 21.9% / 31.1% | ✓ 收益最大 |

**④ DPO 是一个被完整定位的负结果（不是没跑出来）。**
偏好数据 143 对、自写训练循环（TRL 0.24 离线 DPO 漏传 `image_grid_thw`，视觉 token 无法 scatter 回位置）。
结果同域 −0.0009、跨域幻觉率 28%→28%（**未降**，而降低幻觉正是引入 DPO 的目标）。三条根因：

1. **50.3% 的 chosen 本身带错**（chosen 是「4 次采样里最好的」，不是对的）→ 梯度方向有一半是反的；
2. **错误性质超出 DPO 能力**：38.9% 的残余错误在 4 个独立模型上稳定复现，
   是「看错了」（感知层）不是「选错了」（决策层）。同一批错误的对照：
   768px（加信息）−78%，DPO（调分布）**0%**；
3. **偏好数据与目标域完全异分布**：143/143 全是同域合成 heavy 档，而幻觉现场在英文收据域。

⇒ **瓶颈在信息获取，不在决策偏好。** 结论是停止 DPO 调参，把精力转向分辨率与知识注入。

**⑤ 自动 prompt 优化：见效，但功劳在「发现漏字段」，不在「措辞更好」。**
用 DSPy 的 GEPA（反射式优化器，只改 instruction）在跨域上跑一轮：val F1 **0.5205 → 0.7490**
（80 秒 / ¥0.46）。但三组对照把归因钉死了 —— 留出 100 条评测集、唯一变量是 prompt：

| 组 | prompt | F1 | P | R | 幻觉率 |
|---|---|---:|---:|---:|---:|
| A | 手写 3 字段（原 baseline） | 0.4408 | 0.7302 | 0.3157 | 0.090 |
| **B** | **手写 8 字段**（机械补清单，其余一字不动） | **0.7085** | 0.6973 | **0.7201** | **0.210** |
| C | GEPA 优化版 | 0.6830 | 0.6712 | 0.6952 | 0.250 |

⇒ **补字段 +26.8pt，GEPA 的措辞规则 −2.6pt**（在它自己选候选的 40 条 valset 上也是
B 0.7734 > C 0.7447，两个数据集同向 ⇒ **过拟合小验证集**）。

**为什么 C 会输（按字段拆开看，是均匀小亏、无单点崩溃）**：最大一块是 `tel`（−7 tp / +10 fp，
FP 合计 201 → 219），其余字段各亏 0~3。原因是它替换上来的那条**激进召回规则** ——
「必须逐项检查顶部/底部/页脚/边角」「只要图中出现，就应提取」。
**同一条规则在"漏抽 4 个字段"时是解药，字段补齐之后就过量了。**

> ⚠️ 版本更正：早前这里写的是「GEPA 把值规范化成去空格、还加了 `tips`」——
> 那其实是**迭代 1 的中间候选**（val 0.6413），**迭代 2 它自己全改掉了**。
> 导出的最终版明写「字段值必须严格保留图片中的原始写法，**包括空格**」，字段清单无 `tips`。
> 面试官真去读 `outputs/dspy_optimized_flat.txt` 会发现和旧描述相反，所以已按日志更正。

**这条结论的真实价值：跨域短板里有相当一部分是 prompt 缺陷，不是模型缺陷。**
3 字段 prompt 把 recall 天花板压在 **0.4168**（真值 643 个字段里只点名了 268 个），
⑤ 档原 0.4408 = 天花板的 75.7%；补字段后天花板抬到 **0.9907**，实得 **0.7085**。

**但这条不能外推到本地 ②/③ —— 对照已跑完：**

| 档 | prompt | F1 | P | R | 幻觉率 |
|---|---|---:|---:|---:|---:|
| ② 零样本 | 3 → 8 字段 | 0.3190 → **0.4691** | 0.5193 → 0.4449 | 0.2302 → **0.4961** | 0.16 → **0.59** |
| ③ SFT | 3 → 8 字段 | 0.2842 → **0.3752** | 0.4467 → 0.3401 | 0.2084 → **0.4184** | 0.28 → **0.73** |

召回同样翻倍（约 2.1×，天花板对本地也存在），但**精确率同时塌掉** ——
本地 2B 把「找不到的字段可省略」彻底忽略，照着 8 个字段名逐条填空，抽不出来就编：
③ 平均每张吐 **8.0 个键**而真值只有 6.43 个；`subtotal` 在 23 张本不存在的收据上编了 **23 次（100%）**。

⇒ **正确读法是「天花板达成率」：② 55%→50%、③ 50%→42%、⑤ 76%→73%。**
同档换 prompt 几乎不动，**50% vs 73% 这个跨档差距才是真差距** ——
prompt 只决定天花板高度，模型能力决定能接近多少。

**⑥ 商用 API 不是「上界」，而是一个更贵的对照。**
同域 0.9681 与本地微调 0.9782 只差 1.0pt；跨域 0.4408 高于本地两档，但三档都没上到 0.5。
失败结构最能说明问题：DeepSeek 的 108 个错误字段里，**「文本显著误读」占 26.9%**
（本地 SFT 的 74 个错误里只有 5 个），且错误率最高的三个字段 ——
**项目名称 26.5% / 供应商 21.6% / 日期 18.6%** —— 全是**没有版式锚点、只能靠领域先验**的字段。
⇒ 它的短板恰好是「缺领域先验」，而这正是微调补上的那一块。
（另注：这是关掉思考模式后的失败分析。开思考时另有 **11 处漏抽 100% 落在 `合计.金额`**，
关掉后**归零** —— 又一条「思考模式反而引入 schema 遵从问题」的旁证。）

## 3. 会被追问的点，以及怎么答

| 追问 | 回答 |
|---|---|
| 「数据是渲染的，不算真实」 | 主动讲：合成 3000 张有 GT，真实域只有 WildReceipt 100 条。**并给出真实域数字**（0.319/0.284），而不是回避。 |
| 「700 源样本就饱和，规模太小」 | 承认。正因为饱和才把精力投向分辨率与词表注入 —— 这是数据量结论的**下游动作**。 |
| 「跨域微调后反而变差」 | 承认。召回只掉 9.5%，下降主要来自精度 → 「小数据微调放大幻觉倾向」，非灾难性遗忘。这正是 DPO 的动机，而 DPO 没解决（已归因）。 |
| 「为什么不做 RAG」 | **评估过，不需要**：可纠正的候选集是闭集，4 个字段共 293 个值，全量注入只有几百 token；上向量库省不下成本，反而引入召回失败。 |
| 「词表阈值怎么定的」 | 扫参取的**边际有效率拐点**：0.60→0.50 时新增改动 92% 有效，0.50→0.40 掉到 43%。 |
| 「日期为什么默认不纠正」 | 日期收益依赖「日期池有限」这一数据特性；真实场景是连续值，`06-26` 与 `06-25` 相似度 0.91 会混淆相邻日期。要用手动 `--include-date`。 |
| 「你的小模型凭什么比商用 API 高？」 | 数据就是答案：同域 0.9782 vs 0.9681，差 1.0pt，其实**基本打平**，赢的是「闭集字段 + 固定版式」这类领域先验。失败结构也对得上 —— API 的显著误读占 26.9%（本地 SFT 只有 5/74），错误集中在项目名称/供应商/日期。跨域确实它更强（0.4408 vs 0.319），但两档都还远不能用于生产。 |
| 「API 那档一开始跑出来只有 0.86，为什么？」 | 主动讲：那是数据管道的 bug，不是模型能力 —— 102 条里 16 条空响应/半截响应被静默当成有效结果存了下来。修掉之后 0.9681。**这个例子正好说明评测数字异常时该先查管道。** |
| 「API 你开思考模式了吗？」 | 开过，后来关掉了。DeepSeek **默认就开**思考，而关掉后同域 0.9546→**0.9681**、跨域 0.4217→**0.4408**，两格都更高、成本降到约 1/7。结构化抽取是「感知 + 格式化」，不需要推理，思考反而诱发对图面的过度解释（漏抽 `合计.金额` 那 11 处也是关掉后归零的）。 |
| 「跨域才 0.44，是不是模型不行？」 | **先澄清口径**：跨域用的是内置 3 字段 prompt，真值 643 个字段里只点名了 268 个 ⇒ recall 天花板 **0.4168**，0.4408 拿到天花板的 75.7%。把字段补齐到 8 个（天花板 0.9907）后是 **0.7085**。所以这一格衡量的是「prompt+模型」的组合。**但本地 ②/③ 我也换过 prompt 了**：召回同样翻倍，精确率却塌了、幻觉率飙到 0.59/0.73，达成率仍只有 50%/42%（API 是 73%）—— **那 20 多个点才是真·感知差距。** |
| 「本地档也换 8 字段 prompt 会怎样？你试过吗？」 | 试过了。② 0.3190→**0.4691**、③ 0.2842→**0.3752**；召回都翻倍（0.230→0.496、0.208→0.418），说明天花板确实压着它们。**但精确率同时从 0.52/0.45 掉到 0.44/0.34，幻觉率 0.16/0.28 → 0.59/0.73** —— 它把「找不到就省略」这条彻底忽略了，照着 8 个字段名逐条填空：③ 平均每张吐 8.0 个键而真值只有 6.43 个，`subtotal` 在 23 张本不存在的收据上编了 23 次。所以同一批数字在 ②/⑤ 上含义相反：**对 API 是 prompt 缺陷，对本地是感知能力。** |
| 「DSPy 那轮优化出什么了？」 | 一句实话：**它最大的贡献是发现了 prompt 漏字段，而不是把措辞写得更好。** 三组对照（3字段 / 人工补到 8 字段 / GEPA 版）在留出集上是 0.4408 / **0.7085** / 0.6830 —— 补字段 +26.8pt，它的措辞规则 **−2.6pt**，在它自己选候选的验证集上也是这个顺序 ⇒ 过拟合。它的价值是**把「prompt 有结构性缺陷」这件事自动查了出来**。⚠️ 追问细节别说错：它**中间那版**确实写过「去空格 + 加 tips」这类错规则，但下一轮自己删了，**导出的是干净版**。 |
| 「幻觉率 0.59/0.73 你打算怎么压？」 | 试过最便宜的那条路：**把指令写狠**。8 字段 prompt 里把「找不到的字段可省略」换成强规则段（不存在就完全不输出该键、不要 null/空串/占位符、严禁按常理推测编造），字段清单句与输出格式句**一字未动**。结果**压不住**：幻觉率只降 2–5 个点（0.59→0.54、0.73→0.71），F1 反掉 1 个点以上，**tp 掉 9–11 而 fp 几乎不动**（398→401 / 522→520）；③ 的 `tax` 甚至**多编了一个**。输出键数也没动（8.00→8.00）⇒ **它不是「知道该省却硬要编」，是真心认为那些字段就在图上**，所以「不存在就别输出」这句话对它无从触发。这和 DPO 的归因是同一个结论：**瓶颈在感知层**，该动的是分辨率 / 真实数据 / 字段级裁剪，不是 prompt。 |
