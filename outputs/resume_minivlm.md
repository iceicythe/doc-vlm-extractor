## A. 简历写法

### 版本 1 · 标准版（推荐，5 条）

**图文多模态文档结构化提取系统** ｜ 个人项目 ｜ 2026.07 – 2026.09

- 基于 **Qwen3-VL-2B + QLoRA**，在 **RTX 4060 Laptop 8GB 单卡**上完成**工程材料清单**（表头 + 明细 + 合计七字段）的端到端结构化抽取；自建渲染-退化数据管线生成 **3,000 张**合成单据，同分布字段级 F1 **0.982**、JSON 合法率 **100%**、幻觉率 **0%**，峰值显存 4.03 GB；**同域 F1 略高于商用大模型基线**（`deepseek-flash` 0.9681，全部 API 花费仅 ¥1.5）。
- 独立设计 **6 组消融**（输入分辨率 384/512/768px × 数据量 25/50/100% × 冻结视觉塔），定位「**输入分辨率是主导因素**」——384→768px 提升 1.7pt 且增益全部来自重度退化档；残余错误 100% 降为字符级误读，语义混淆与结构类错误归零。
- 实现**两条不改权重的效果提升路径**：**(a) 标准词表知识注入**（精确命中 + 相似度 0.50 / 间隔 0.05 三级保守规则），零样本 F1 **0.7349 → 0.7870**、改动 183 处修复 169 处、**改坏 0 处**（结构性保证）；并在三个能力档位（2B 零样本 / 商用 API / 2B SFT）上验证收益与基座能力成反比（+0.0522 / +0.0109 / −0.0003），证明微调已将词表内化进权重。**(b) DSPy（GEPA）自动 prompt 优化**：以留出集三组对照（手写 3 字段 / 人工补至 8 字段 / GEPA 版 = 0.4408 / **0.7085** / 0.6830）证明**收益来自自动发现未微调档位的「prompt 漏字段」这一结构性缺陷，而非措辞优化**，并据此定位 API 档跨域短板的主因。
- 完成 **DPO 后训练并给出完整归因的负结果**：因 TRL 0.24 离线 DPO 漏传视觉位置参数而自写训练循环，通过偏好数据质量门与跨模型错误一致性分析证明「**瓶颈在感知层而非决策层**」（38.9% 错误在 4 个独立模型上稳定复现）。
- 基于 **Gradio** 实现四栏对照 Demo（同模型同输入，唯一变量为 LoRA adapter），29 项 CPU 自检全绿；跨语言跨域泛化（WildReceipt n=100：本地 0.284/0.319、商用 API 0.4408，**该口径 recall 天花板仅 0.4168**）作为已量化短板列入后续方向，并补做「换 8 字段 prompt」对照把 **prompt 天花板与感知能力分离**（本地仅达天花板 50%/42%，API 达 73%）。

### 版本 2 · 精简版（3 条，版面紧张时用）

**图文多模态文档结构化提取**（Qwen3-VL-2B + QLoRA，个人项目，2026.07–2026.09）

## B. 面试自述（约 60 秒）

> 我做的是一个面向工程单据的图文多模态结构化抽取系统。输入是一张工程材料清单的照片，输出是结构化 JSON —— 表头有项目名称、供应商、单据编号、日期，明细是序号、名称、规格型号、单位、数量、单价、金额，还有合计。这跟造价软件的「材料明细表」是同一套结构。
>
> 因为只有一张 8GB 显卡，我用 Qwen3-VL-2B 做 QLoRA 微调，数据是自己渲染+退化生成的 3,000 张。同分布字段级 F1 做到 0.982，JSON 合法率 100%。
>
> 后面我主要做了三件事：一是六组消融，发现**输入分辨率是主导因素**而不是数据量，768px 能到 0.9953；二是**知识注入**，用训练集值域建标准词表做保守纠错，零样本 F1 从 0.7349 提到 0.7870，改坏 0 处 —— 而且 SFT 之后只需改 1 处，说明词表已经被微调学进去了；三是我跑了一个 **DPO 但没成**，然后把它完整归因了：一半的偏好对里 chosen 本身就带错，而且 38.9% 的错误在四个独立模型上稳定复现，说明是「看错了」不是「选错了」，DPO 只能调分布、不能加信息。
>
> 还做了个 Gradio 的四栏对照 Demo，同一个模型同一个输入，唯一变量是 LoRA adapter，可以现场演示微调前后的差距。
>
> （若时间够，加这 20 秒 —— JD 第 1 条就写着「自动化 prompt 生成」）
> 最后我还试了**自动 prompt 优化**，用 DSPy 的 GEPA 在跨域上跑了一轮。它的分数涨得挺多，但我做了三组对照才发现：**涨的全是「它自己发现手写 prompt 漏了 4 个字段」，不是它把措辞写得更好** —— 它额外加的那些格式规则反而是负贡献。我又把同一个 prompt 喂给本地两个档位，**召回同样翻倍，但精确率塌了、幻觉率从 0.2 飙到 0.7** —— 它照着字段清单逐条填空，抽不出来就编。所以我最后的结论是：**prompt 只决定天花板的高度，能接近多少是模型能力的事**；同一个问题在商用大模型上是 prompt 缺陷，在 2B 上就是感知能力。

## C. 可能被追问的三个点

| 追问 | 建议回答 |
|---|---|
| 「你的数据是合成的，真实场景能用吗？」 | 直说局限，然后给真实域数字（WildReceipt 英文收据 n=100：零样本 0.319 / 微调后 0.284）。再补一句：跨域掉下来的是**精度**不是召回，属于小数据微调放大幻觉倾向。 |
| 「知识注入和 RAG 什么关系，为什么不上检索？」 | 「评估过不需要：可纠正的候选集是闭集，4 个字段才 293 个值，全量注入只几百 token，上向量库省不下成本还引入召回失败。」**不要说「我做了 RAG」。** |
| 「8GB 显存够吗，怎么做取舍？」 | 报数字：峰值 4.03 GB、推理 8.9s/张。取舍是**可以冻结视觉塔**（消融实测只差 0.0008）；另外 Windows 上 FA2 不可用、`torch.compile` 对视觉算子编译失败，都是自动降级到 eager。 |
| 「你的 2B 小模型凭什么比商用 API 高？」 | 因为任务是**闭集字段 + 固定版式**，微调把版面结构和词表都内化了；但要说实话 —— 差距只有 1.0pt（0.9782 vs 0.9681），本质是**打平**，不是碾压。API 的错误结构也对得上：显著误读占 26.9%（本地 SFT 只有 5/74），错误集中在项目名称/供应商/日期。跨域它确实更强（0.4408 vs 0.319），但两档都还远不能用于生产。 |
| 「跑出来数字不好看，你怎么判断是模型问题还是别的问题？」 | 举 API 档那个例子：第一版同域只有 0.8622，JSON 合法率 84.3%。查下去发现是**管道 bug** —— 102 条里 16 条空响应/半截响应被静默存成有效结果，整条按 0 分计。修掉后 0.9681。结论：**指标异常先查管道，再谈模型。** |
| 「自动 prompt 优化（DSPy）跑出什么了？」 | 数字是跨域 0.4408→**0.6830**，但我没停在数字上 —— 加了一组「人工机械补齐字段」的对照，它是 **0.7085**，比 DSPy 还高。所以结论是：**GEPA 的贡献是「自动发现了 prompt 漏字段」这个诊断，不是它的措辞**；它多写的规则（激进召回 / 逐项检查边角）是过拟合 40 条验证集，两个数据集上都是负贡献。**prompt 优化的收益要拆开看，不能只看涨了多少。** ⚠️ 别说错版本：它**中间那版**确实写过「去空格 + 加 tips」，但下一轮自己删了，导出的是干净版（面试官可能真去读那个 txt）。 |
| 「跨域为什么只有 0.44？」 | 先澄清口径：跨域用内置 3 字段 prompt，真值 643 个字段里只点名了 268 个 ⇒ **recall 天花板 = 0.4168**，0.4408 拿到天花板的 75.7%（不是"贴着"）。补齐字段后是 **0.7085**。所以这一格衡量的是「prompt + 模型」的组合。 |
| 「那本地两档也换 8 字段 prompt，是不是也能涨到 0.7？」 | **不能，而且这个对照我跑了。** ② 0.3190→0.4691、③ 0.2842→0.3752：召回确实翻倍（0.230→0.496、0.208→0.418），说明天花板对它们也存在；**但精确率同时从 0.52/0.45 塌到 0.44/0.34，幻觉率 0.16/0.28 → 0.59/0.73**。原因是它把「找不到就省略」彻底忽略，照着 8 个字段名逐条填空 —— ③ 平均每张吐 8.0 个键而真值只有 6.43 个。**换成「天花板达成率」看：② 55%→50%、③ 50%→42%、API 76%→73%（同档几乎不动），50% vs 73% 这个跨档差距才是真差距。** |
| 「你试过用更强的指令压住幻觉吗？」 | 试过，**压不住**。8 字段 prompt 里把「找不到可省略」换成强规则段（不存在就完全不输出该键 / 不许 null、空串、占位符 / 严禁按常理推测编造），字段清单句与输出格式句**一字未动**：幻觉率只降 2–5 个点，而 **F1 反掉 1 个点以上**，tp 掉 9–11、**fp 几乎不动**（398→401 / 522→520）。⇒ 它不是「知道该省却硬编」，是**真心认为图上就有那些字段**，「不存在就别输出」这句话对它无从触发。和 DPO 的归因是同一个结论：**瓶颈在感知层，不在 prompt / 决策层。** |
